# 实验配置组 v0.1

**状态**　v0.1

## 1. 目标

业务的 Agent、Skill 和 Prompt 配置以各自的 JSON 格式存在。配置人员需要把多个 Agent 放进同一个实验组，为每个 Agent 挑选依赖的资产版本，并在发布前看到运行时将收到的数据。运行时已经知道实验 tag，可以用一次请求拿到整组配置。

首版面向一个自托管实例和一个团队。实验 tag 是调用方已确定的配置选择键。流量分配、实验指标、跨实例同步和运行 Agent 由调用方负责。配置内容通过 JSON 导入，原始字段保留在各资产的 `config` 下。

## 2. 使用流程

1. 配置人员登记 JSON Schema，选择资产类型，再用表单或 JSON 编辑器创建 Agent、Skill 和 Prompt。
2. 配置人员创建实验组，在同一页面添加 Agent，展开每个 Agent 并为每个依赖选择资产和版本。
3. 配置人员预览已保存草稿的完整 JSON，确认后发布。运行时用实验 tag 读取当前发布。
4. 配置人员可查看历史发布，并将某个历史版本重新设为当前版本。运行日志可以记录 `releaseId`，以便重放历史配置。

## 3. 配置样例

以下名称和配置仅用于演示。两个 Agent 在同一个实验组内同时存在。

```text
support-routing  →  release support-routing@1
├── intake           →  support-agent@12
│   ├── knowledge    →  knowledge-search@3
│   └── instructions →  intake-prompt@7
└── dispatch         →  dispatch-agent@8
    ├── knowledge    →  knowledge-search@4
    └── ticket       →  ticket-lookup@2
```

`intake`、`dispatch` 和 `knowledge` 是配置组内的绑定名。Agent 绑定名在组内唯一，依赖绑定名在所属 Agent 内唯一。相同的资产可以在两处使用不同版本。绑定随配置组编辑，同一个 Agent 版本可在不同配置组里关联不同依赖。

## 4. 功能要求

| 编号 | 要求 |
|---|---|
| FR-01 | 创建并列出 Schema 和资产。支持 JSON Schema Draft 2020-12，资产种类为 Agent、Skill、Prompt。Schema 和资产都有稳定标识及不可变版本。 |
| FR-02 | 允许导入对象型 JSON。创建资产版本时选择一个同类型的 Schema 版本并验证数据。通过验证的资产版本可以被实验组选用。 |
| FR-03 | 实验组可绑定多个 Agent 版本。每条 Agent 绑定可绑定多个 Skill 或 Prompt 版本。保存时验证资产版本存在、类型正确、绑定名唯一。 |
| FR-04 | 单个实验组详情页显示配置树、各节点的版本和当前发布。支持增删绑定、切换版本和预览草稿的实际 JSON。 |
| FR-05 | 草稿和已发布数据独立。发布前再次验证草稿及引用，生成包含实际 JSON 的不可变快照。快照入库和切换 tag 在同一事务完成。 |
| FR-06 | `GET /api/v1/config?tag=support-routing` 返回当前快照，加上 `releaseId` 可读取指定历史发布。tag 尚未发布、tag 未知或指定的发布 ID 未知时返回 404。 |
| FR-07 | 支持查看发布历史和重新激活历史发布，草稿可继续编辑。重复提交一次成功的发布可得到原发布 ID。 |
| FR-08 | 保存草稿、发布和激活历史发布均使用版本前置条件。若其他操作者已更新相应状态，返回冲突并提示刷新。 |

## 5. 验收用例

| 编号 | 操作与预期 |
|---|---|
| AC-01 | 导入两种字段结构的 Agent JSON。合法数据成功建立版本，缺少必填字段的导入失败，也不会出现空资产或新版本。 |
| AC-02 | 将样例中的两个 Agent 加入实验组。树状页面和预览同时显示 `knowledge-search@3` 和 `knowledge-search@4`。一个 Agent 的依赖调整不改变另一个 Agent。 |
| AC-03 | 发布样例，再创建 `knowledge-search@5` 并修改草稿。按 tag 读取仍返回原来的两个 Agent 和各自的 `@3`、`@4`，且返回同一个 `releaseId`。 |
| AC-04 | 发布第二版后，按 tag 读到第二版。按第一版 `releaseId` 读到第一版。重新激活第一版后，tag 回到第一版，第二版仍可精确读取。 |
| AC-05 | 引用缺失、类型不匹配或模拟发布事务失败时，返回明确错误。原草稿或原发布仍完整可读。空草稿不能发布。 |
| AC-06 | 两个客户端基于同一草稿版本保存，只有一个成功。发布和读请求并发时，任一响应里的配置全部来自同一个已提交的发布。 |
| AC-07 | 重放已成功的发布请求会返回相同 `releaseId`。如果此后已经回滚或发布了新版本，重放不会移动当前指针。 |

## 6. 首版边界

- 浏览器 UI 和 API 默认供 localhost 使用。面向多人或公网的部署需要补鉴权、权限和审计。
- 数据库保存 JSON 及发布历史。配置中遇到凭据时，由业务传凭据引用并在自身运行环境中解析。
- 首版支持实验组、Agent、Skill 或 Prompt 这两层关联。资产之间的任意级联依赖和跨实例引用留待后续设计。
- 通用表单优先覆盖常见属性，复杂 Schema 通过 JSON 编辑器操作。两种输入走同一份服务端验证。
